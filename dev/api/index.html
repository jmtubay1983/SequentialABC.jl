API Reference

All types and functions exported by SequentialABC.jl.

Each @autodocs block uses Private = false so that only the exported (public) API is rendered; internal helpers such as perturb are excluded.

Sampler configuration

SequentialABC.ABCSMCConfig — Type
ABCSMCConfig{P,Tr,D,K,S}

Configuration struct for the Toni et al. (2009) ABC‑SMC sampler.

Fields:

  • prior::P — log‑density function π(θ_raw) on the raw parameter space
  • sampleprior::Function — sampler: (rng) → θraw from the prior (for gen‑1 init)
  • transform::Tr — θraw → θmodel (project‑specific parameter map)
  • distance::D — (summarysim, summaryobs) → Real
  • kernel::K — perturbation kernel: log K(θnew | θold, Σ)
  • Σ::Matrix{Float64} — perturbation covariance
  • Σ_inv::Matrix{Float64} — precomputed inverse covariance
  • simulator::S — simulator backend (AgentsSimulator or ContinuousSimulator)

Constructor computes Σ_inv automatically from Σ.

make_state(cfg::ABCSMCConfig, ::Type{Tθ}, N::Int, ε0::Float64, base_seed::Int)

Construct an empty generation‑0 state. Tθ is the raw parameter type from the prior; Tsum starts as Any and gets retyped in initialize! from the first simulation result.

Sampler state

SequentialABC.ABCSMCState — Type
ABCSMCState{C,Tθ,Tsum}

Mutable sampler state for Toni et al. (2009) ABC‑SMC.

Fields:

  • cfg::C — ABCSMCConfig
  • θ::Vector{Tθ} — particles at current generation
  • w::Vector{Float64} — normalized importance weights
  • summaries::Vector{Tsum} — cached summaries
  • dists::Vector{Float64} — cached distances d(si, sobs) of accepted particles
  • ε::Float64 — current tolerance
  • gen::Int — current generation index
  • ess::Float64 — effective sample size
  • base_seed::Int — base RNG seed for deterministic replication
  • n_attempts::Int — accepted‑particle attempts this generation (diagnostic)
  • n_resamples::Int — cumulative number of population resamplings (diagnostic)

Simulator backends

SequentialABC.AgentsSimulator — Type
AgentsSimulator(model_builder, step!, summary, steps)

Agents.jl backend. model_builder(θ, rng) builds the model on the given RNG (Agents.jl models own an rng at construction — e.g. StandardABM(...; rng = rng), accessed via abmrng(model)), so the entire particle simulation consumes one deterministic stream. step!(model, rng) advances the model by one step, summary(model) extracts the summary statistic after steps steps.

source
SequentialABC.ContinuousSimulator — Type
ContinuousSimulator(model_builder, evolve, summary)

Continuous (ODE/PDE/SSA) backend. model_builder(θ) builds the problem, evolve(problem, rng) runs it to completion, summary(final_state) extracts the summary statistic.

Perturbation kernel

SequentialABC.GaussianKernel — Type
GaussianKernel

Perturbation kernel for Toni et al. (2009) ABC‑SMC: θnew = θold + ε, ε ~ 𝒩(0, Σ)

Implements the exact log‑pdf and perturbation steps used in the paper.

source
SequentialABC.GaussianKernel — Method
(K::GaussianKernel)(θ_new, θ_old, Σ_inv, logdetΣ) -> Float64

Full log‑density of 𝒩(θold, Σ) at θnew, including the normalizing constant:

log 𝒩(x | μ, Σ) = -½ (x-μ)' Σ⁻¹ (x-μ) - ½ (k log 2π + logdetΣ)

Numerically identical to Distributions.logpdf(MvNormal(μ, Σ), x) (unit-tested).

Importance weights and ESS

SequentialABC.ess — Method
ess(w::AbstractVector{<:Real}) -> Float64

Effective sample size: ESS = 1 / Σi wi²

For N=1, ESS is defined as 1.0 (guard against division issues).

source
SequentialABC.importance_weight — Method
importance_weight(cfg::ABCSMCConfig, θ_prop::AbstractVector,
                  θ_prev::Vector, w_prev::Vector{Float64}) -> Float64

Toni et al. (2009) importance weight:

w ∝ π(θprop) / Σj wprev[j] · K(θprop | θ_prev[j], Σ)

Implemented in log‑space for numerical stability: log w = log π(θprop) - logsumexp( log(wprev[j]) + log K(θprop | θprev[j], Σ) )

The prior is a log‑density on the raw parameter space; the transform is applied only at simulation time.

source
SequentialABC.systematic_resample — Method
systematic_resample(w::AbstractVector{<:Real}, rng::AbstractRNG) -> Vector{Int}

Low‑variance systematic resampling (Toni et al. 2009 use resampling when the effective sample size falls too low; systematic resampling has the smallest variance among standard schemes).

Algorithm:

  1. Draw u ~ U(0, 1/N)
  2. Place N equally spaced positions u + (i−1)/N on the cumulative weight staircase
  3. Return the bin indices those positions fall into

The RNG is passed explicitly — never the global RNG — so resampling is as deterministic and replayable as every other stochastic step.

Tolerance schedules

SequentialABC.FixedSchedule — Type
FixedSchedule(εs::AbstractVector{<:Real})

Callable tolerance schedule (state, t) -> εs[t] for run_smc!. Toni et al. (2009) style hand-picked schedule; must be non-increasing. Generation 1 uses state.ε (the initial tolerance), so index t ≥ 2 entries are consumed for a T-generation run started from gen 0 — pass the full intended schedule ε_1, ε_2, …, ε_T and it is indexed directly by t.

source
SequentialABC.QuantileSchedule — Type
QuantileSchedule(q)

Callable tolerance schedule (state, t) -> ε_t for run_smc!: each generation uses the q-quantile of the previous population's distances. Toni et al. (2009) used a fixed schedule; quantile adaptation is the standard post‑Toni optimization and converges to small ε without manual tuning.

source
SequentialABC.epsilon_quantile — Method
epsilon_quantile(state::ABCSMCState, q::Real) -> Float64

Adaptive tolerance: the q-quantile of the current population's accepted distances d(s_i, s_obs) (cached in state.dists).

Monotone non-increasing by construction: every stored distance is ≤ the tolerance that accepted it, so any quantile of them is ≤ state.ε. An explicit min guard is kept as belt-and-braces.

Typical choice q = 0.5 (median), used to define ε_{t+1} from population t.

Sampler drivers

SequentialABC.initialize! — Method
initialize!(state::ABCSMCState, summary_obs;
            max_attempts::Int=10_000)

Generate generation‑1 from the prior. Follows Toni et al. (2009) exactly:

For i = 1…N:

  1. Sample θ_raw from prior (deterministic RNG seeded from (gen, i, attempt, base))
  2. Simulate transform(θ_raw) → s(θ)
  3. Compute distance d = distance(s, summary_obs)
  4. If d ≤ ε accept, else repeat from step 1

Accepted particles get uniform weights 1/N (proposal = prior ⇒ ratio cancels). Particles are stored on the raw parameter space (where the prior is defined); the transform is applied only inside simulation. The first accepted summary determines the type Tsum; subsequent summaries are typed as Vector{Tsum}.

source
SequentialABC.run_generation! — Method
run_generation!(state::ABCSMCState, summary_obs;
                ε::Float64, M::Int=1, max_attempts::Int=10_000)

Run a single generation of ABC‑SMC with redraw‑until‑accepted.

For each particle i:

  1. Resample ancestor j according to current weights
  2. Perturb θ = perturb(θ_prev[j], Σ)
  3. Simulate (M replicates) → s̄
  4. Compute distance d
  5. If d ≤ ε accept, else redraw with new attempt counter

Ensures no zero‑weight particles ⇒ normalization and ESS always well‑defined.

source
SequentialABC.run_smc! — Method
run_smc!(state::ABCSMCState, summary_obs;
         T::Int, schedule, M::Int=1, max_attempts::Int=10_000,
         checkpoint_dir::Union{Nothing,AbstractString}=nothing)

Run ABC‑SMC for T generations with adaptive tolerance schedule.

schedule should be a function: schedule(state, t) -> ε_t

If checkpoint_dir is given, an atomic checkpoint is written after initialization and after every completed generation (state_gen_XXX.jls). Restart by loading with load_latest_state(checkpoint_dir, cfg) and calling run_smc! again with the same directory — the run resumes from state.gen + 1.

Deterministic RNG

SequentialABC.make_particle_seed — Method
make_particle_seed(gen::Int, i::Int, attempt::Int, m::Int, base::Int) -> Int

Deterministic seed for particle simulation.

The attempt counter is essential: without it, redraw‑until‑accepted would replay the identical rejected proposal forever with a deterministic RNG. The seed is a pure function of (gen, i, attempt, m, base) → full replay across Slurm nodes and restarts.

SequentialABC.load_latest_state — Method
load_latest_state(dir::AbstractString, cfg) -> ABCSMCState

Load the highest‑generation checkpoint from dir and reattach cfg (an ABCSMCConfig; it is intentionally not serialized — checkpoints carry data only). Resume a run with run_smc!(state, summary_obs; T=…, schedule=…), which continues from state.gen + 1 using the stored deterministic seeds — the resumed trajectory is bit‑identical to an uninterrupted one.

source
SequentialABC.save_checkpoint — Method
save_checkpoint(state::ABCSMCState, dir::AbstractString) -> String

Atomically checkpoint the sampler to dir/state_gen_XXX.jls.

Only data is serialized (θ, w, summaries, ε, gen, ess, seeds, counters) — never cfg and its closures. This makes checkpoints portable across Julia versions, code revisions, and Slurm nodes: reload with the same (or updated) cfg via load_latest_state.

Atomicity: the payload is written to a .tmp file first and then renamed. POSIX rename is atomic on the same filesystem, so a job killed mid‑write can never leave a corrupted checkpoint — at worst a stale .tmp file, which the loader ignores.
