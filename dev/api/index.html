Sampler configuration

SequentialABC.ABCSMCConfig — Type
ABCSMCConfig{P,Tr,D,K,S}

Configuration struct for the Toni et al. (2009) ABC‑SMC sampler.

Fields:

  • prior::P — log‑density function π(θ_raw) on the raw parameter space
  • sampleprior::Function — sampler: (rng) → θraw from the prior (for gen‑1 init)
  • transform::Tr — θraw → θmodel (project‑specific parameter map)
  • distance::D — (summarysim, summaryobs) → Real
  • kernel::K — perturbation kernel: log K(θnew | θold, Σ)
  • Σ::Matrix{Float64} — perturbation covariance
  • Σ_inv::Matrix{Float64} — precomputed inverse covariance
  • simulator::S — simulator backend (AgentsSimulator or ContinuousSimulator)

Constructor computes Σ_inv automatically from Σ.

Perturbation kernel

SequentialABC.GaussianKernel — Type
GaussianKernel

Perturbation kernel for Toni et al. (2009) ABC‑SMC: θnew = θold + ε, ε ~ 𝒩(0, Σ)

Implements the exact log‑pdf and perturbation steps used in the paper.

source
SequentialABC.GaussianKernel — Method
(K::GaussianKernel)(θ_new, θ_old, Σ_inv, logdetΣ) -> Float64

Full log‑density of 𝒩(θold, Σ) at θnew, including the normalizing constant:

log 𝒩(x | μ, Σ) = -½ (x-μ)' Σ⁻¹ (x-μ) - ½ (k log 2π + logdetΣ)

Numerically identical to Distributions.logpdf(MvNormal(μ, Σ), x) (unit-tested).

Importance weights and ESS

ess(w::AbstractVector{<:Real}) -> Float64

Effective sample size: ESS = 1 / Σi wi²

source
SequentialABC.importance_weight — Method
importance_weight(cfg::ABCSMCConfig, θ_prop::AbstractVector,
                  θ_prev::Vector, w_prev::Vector{Float64}) -> Float64

Toni et al. (2009) importance weight:

w ∝ π(θprop) / Σj wprev[j] · K(θprop | θ_prev[j], Σ)

Implemented in log‑space for numerical stability: log w = log π(θprop) - logsumexp( log(wprev[j]) + log K(θprop | θprev[j], Σ) )

The prior is a log‑density on the raw parameter space; the transform is applied only at simulation time.

source
SequentialABC.systematic_resample — Method
systematic_resample(w::AbstractVector{<:Real}, rng::AbstractRNG) -> Vector{Int}

Low‑variance systematic resampling (Toni et al. 2009 use resampling when the effective sample size falls too low; systematic resampling has the smallest variance among standard schemes).

Algorithm:

  1. Draw u ~ U(0, 1/N)
  2. Place N equally spaced positions u + (i−1)/N on the cumulative weight staircase
  3. Return the bin indices those positions fall into

The RNG is passed explicitly — never the global RNG — so resampling is as deterministic and replayable as every other stochastic step.

Tolerance schedules

SequentialABC.FixedSchedule — Type
FixedSchedule(εs::AbstractVector{<:Real})

Callable tolerance schedule (state, t) -> εs[t] for run_smc!. Toni et al. (2009) style hand-picked schedule; must be non-increasing. Generation 1 uses state.ε (the initial tolerance), so index t ≥ 2 entries are consumed for a T-generation run started from gen 0 — pass the full intended schedule ε_1, ε_2, …, ε_T and it is indexed directly by t.

Call signature

(sched::FixedSchedule)(state, t, distances) -> ε_t

The distances argument is accepted for interface uniformity but ignored — FixedSchedule is fully prescribed. The 2-arg form (state, t) is preserved for backward compatibility.

source
SequentialABC.QuantileSchedule — Type
QuantileSchedule(q)

Callable tolerance schedule for run_smc!: each generation uses the q-quantile of the previous population's distances. Toni et al. (2009) used a fixed schedule; quantile adaptation is the standard post‑Toni optimization and converges to small ε without manual tuning.

Call signature

(sched::QuantileSchedule)(state, t, distances) -> ε_t

  • distances is the vector from which ε is derived:
    • Non-adaptive mode: state.dists
    • Adaptive mode: state.adaptive.epsilon_selection_distances
  • The 2-arg form (state, t) is preserved for backward compatibility and uses state.dists.

FixedSchedule ignores the supplied distances.

source
SequentialABC.epsilon_quantile — Function
epsilon_quantile(distances::AbstractVector{<:Real}, q::Real,
                 ε_cap::Real=Inf) -> Float64

Adaptive tolerance: the q-quantile of the supplied accepted distances.

Typical choice q = 0.5 (median), used to define ε_{t+1} from population t.

Monotonicity and the ε_cap guard

The monotonicity story depends on the distance source:

  • Non-adaptive mode (state.dists): monotone non-increasing by construction — every stored distance is ≤ the tolerance that accepted it, so any quantile of them is ≤ the previous ε.
  • Adaptive mode (state.adaptive.epsilon_selection_distances): the vector is recomputed at the generation boundary under the newly estimated weights. Recomputed distances are not bounded by the previous tolerance, so monotonicity does not follow from construction alone — the explicit min(ε_new, ε_cap) guard is load-bearing there (it is what keeps ε from growing past the caller's cap), not merely belt-and-braces. It remains belt-and-braces in non-adaptive mode.

Distance source

  • Non-adaptive mode: pass state.dists (acceptance distances from the completed generation).
  • Adaptive mode: pass state.adaptive.epsilon_selection_distances (recomputed at the generation boundary under newly estimated weights).

epsilon_quantile(state::ABCSMCState, q::Real) -> Float64

Backward-compatible wrapper: uses state.dists (acceptance distances) and caps at state.ε. Prefer epsilon_quantile when you have a specific distance vector.

Adaptive distance scaling

Per-key inverse-distance scaling for ABC-SMC summaries, enabled with the adaptive keyword of run_smc / run_smc!. With the ordinary Euclidean base distance (p = 2), both summaries are pre-scaled by the inverse scale weights before their weighted Euclidean distance is evaluated. Pre-scaling both sides by adaptive inverse-scale weights gives the same shape to the base distance; if the base distance is already weighted (e.g. a WeightedL2 or a Mahalanobis distance), the two weightings compose (product/matrix composition) — see the internal adaptive_distance docstring for details.

adaptive = AdaptiveDistanceConfig(
    StandardDeviationScale(),
    NumericalPolicy(constant_policy = :clamp),
)
state = run_smc(cfg, s_obs; N = 1000, T = 10, adaptive = adaptive)

Numerical policy (floor, constant_policy, max_weight) lives only in NumericalPolicy — strategy types identify the estimator alone. The runtime state is internal: inspect it read-only through state.adaptive.

Notes on edge cases: For N = 1, the unweighted std is NaN (path 2 of the policy) — under default constant_policy = :error the first adaptive boundary throws ArgumentError. A nominally constant key with floating-point rounding can have scale < floor → weight 1/floor (possibly > max_weight; max_weight is the :clamp value, not a global cap). See NumericalPolicy for details.

This release is ABC-SMC-only. Estimated weights use the previous accepted population's unweighted standard deviation (so N ≥ 2 is required to obtain finite positive scales without invoking path 2 for regular keys). Estimated strategies initialize with unit weights; FixedScale uses its explicit weights from generation 1. Immediately before every generation actually executed after the first, the implementation estimates that generation's weights, recomputes the preceding population's distances, derives epsilon, and freezes both weights and epsilon. It performs no update after the final requested generation. The recomputed epsilon_selection_distances are not bounded by the previous tolerance (see epsilon_quantile for monotonicity details and the role of the ε_cap/min guard). Decompiled tolerances are frozen in state.adaptive.epsilon for gen_applied and never change mid-generation.

MAD scaling, importance-weighted scale estimation, rejected/all-particle scale estimation, selected update generations, prior-predictive initialization, weight-ratio bounds, and adaptive-distance integration with ABC-MCMC or ABC-PMC are deferred. Performance note (deferred): for a large population per generation, the per-particle recomputation of epsilon_selection_distances under new weights is cheap in general, but can be optimized later to scale the observed summary once per generation and re-use a lookup — see the associated post-merge tracker for details. This is not a claim of full pyABC parity.

source
SequentialABC.NumericalPolicy — Type
NumericalPolicy(; floor = 1e-8, constant_policy = :error, max_weight = 1e6)

Single source of truth for numerical policy, shared across all strategies. Fields:

  • floor — lower bound applied to a raw scale estimate before inverting it (guards against division by near-zero variance)
  • constant_policy — what to do when a key has zero or non-finite scale: :error (throw), :ignore (weight 0.0), or :clamp (weight = max_weight)
  • max_weight — the weight used by constant_policy === :clamp

Scale paths in detail (StandardDeviationScale)

For each key the estimator computes the unweighted standard deviation scale of the accepted replicate summaries and then takes exactly one of three paths:

  1. Regular path — scale finite and strictly positive: the weight is 1 / max(scale, floor).
    • A near-zero scale below floor (floating-point rounding on a nominally constant key, tiny but nonzero variance) takes this path with max(scale, floor) == floor, receiving weight 1/floor (default 1e-8 → 1e8). Note that this floor-derived weight exceeds max_weight (default 1e6): max_weight is not an upper bound on all weights — it is only the value used by the :clamp branch of path 2. Raise floor (or use constant_policy = :clamp on a detected constant key) if you need a tighter bound; pass floor ≥ 1/max_weight to keep 1/floor ≤ max_weight.
  2. Constant/degenerate path — scale == 0.0 or non-finite (NaN or ±Inf): constant_policy decides — :error throws ArgumentError naming the key, :ignore stores weight 0.0, :clamp stores exactly max_weight.
  3. :ignore weights are re-validated afterwards: if every key took path 2 with :ignore, the all-zero weight vector would degenerate every distance to zero and is rejected with ArgumentError.

N = 1. With a single particle the sample standard deviation of one value is NaN (the corrected estimator is undefined for n = 1), so every key takes path 2 as non-finite. Under the default constant_policy = :error the run fails closed at the first adaptive boundary — the update_adaptive! call before generation 2 — with an ArgumentError; it does not silently produce weights. Choose :clamp or :ignore (or a non-estimated strategy such as FixedScale) to run populations smaller than 2 deliberately.

Belongs to AdaptiveDistanceConfig, never to strategy types.

Sampler drivers

SequentialABC.initialize! — Method
initialize!(state::ABCSMCState, summary_obs;
            max_attempts::Int=10_000)

Generate generation‑1 from the prior. Follows Toni et al. (2009) exactly:

For i = 1…N:

  1. Sample θ_raw from prior (deterministic RNG seeded from (gen, i, attempt, base))
  2. Simulate transform(θ_raw) → s(θ)
  3. Compute distance d = distance(s, summary_obs)
  4. If d ≤ ε accept, else repeat from step 1

Accepted particles get uniform weights 1/N (proposal = prior ⇒ ratio cancels). Particles are stored on the raw parameter space (where the prior is defined); the transform is applied only inside simulation. The first accepted summary determines the type Tsum; subsequent summaries are typed as Vector{Tsum}.

source
SequentialABC.run_generation! — Method
run_generation!(state::ABCSMCState, summary_obs;
                ε::Float64, M::Int=1, max_attempts::Int=10_000,
                resample::Bool=true)

Run a single generation of ABC‑SMC with redraw‑until‑accepted.

For each particle i:

  1. Resample ancestor j according to current weights
  2. Perturb θ = perturb(θ_prev[j], Σ)
  3. Simulate (M replicates) → s̄
  4. Compute distance d
  5. If d ≤ ε accept, else redraw with new attempt counter

Ensures no zero‑weight particles ⇒ normalization and ESS always well‑defined.

resample = false skips the population resampling step that normally fires when ESS < 0.5 N. Ancestor draws of the next generation already sample the weighted population, which is exactly what population Monte Carlo relies on: the weights stay informative instead of being reset to 1/N. The current tolerance still accepts particles, state.ess reports the true ESS and state.n_resamples stays at its previous value. Used by run_pmc.

SequentialABC.run_pmc! — Method
run_pmc!(state::ABCSMCState, summary_obs; T, schedule,
         kernel_rule = :beaumont, M = 1, max_attempts = 10_000,
         checkpoint_dir = nothing) -> ABCSMCState

Advance a PMC population from state.gen + 1 to generation T. schedule is a callable (state, t) -> ε_t (e.g. FixedSchedule or QuantileSchedule) and kernel_rule is the covariance scaling rule — the two engines' contract on resume is the same, so pass the same T, schedule and kernel_rule you started the run with. If state.gen == 0 the prior sample of generation 1 is taken first, exactly as run_smc! does.

See run_pmc for the algorithm, every keyword and the trade-offs.

source
SequentialABC.run_pmc — Method
run_pmc(cfg::ABCSMCConfig, summary_obs; N, T, εs = nothing,
        schedule = QuantileSchedule(0.5), ε0 = Inf, kernel_rule = :beaumont,
        M = 1, base_seed = 1, Tθ = nothing, max_attempts = 10_000,
        checkpoint_dir = nothing) -> ABCSMCState

Population Monte Carlo for approximate Bayesian computation (Beaumont et al. 2009): the same redraw‑until‑accepted population loop as ABC‑SMC, run with the two choices that define PMC.

  1. The perturbation covariance is re‑derived from the population at every generation — Σ_t = scaling_factor(d; kernel_rule) · Cov(θ_{t-1}, w_{t-1}), with kernel_rule = :beaumont (×2) as default. It is adopted at the generation boundary, before any particle of that generation exists, so a single Σ serves the whole generation and its importance weights. run_smc instead keeps cfg.Σ fixed, which is what makes hand tuning matter.
  2. The population is never resampled. The ESS‑triggered systematic_resample step of ABC‑SMC is skipped (resample = false in run_generation!): weights stay informative across generations and the weighted ancestor draws do the importance sampling — that is the mechanism PMC is named for. So state.ess reports the real ESS of each generation rather than resetting to N, and state.n_resamples stays 0, which is the diagnostic that confirms you are running PMC.

Everything else is deliberately identical to run_smc: the perturbation‑corrected weight w ∝ π(θ) / Σ_j w_j K(θ | θ_j, Σ) from importance_weight, deterministic per‑particle streams from make_particle_seed, the same diagnostics, and the same ABCSMCState return value — so weights, plots, checkpointing and benchmark tooling work unchanged.

Keywords

  • N::Int — population size
  • T::Int — total generations, including generation 1
  • εs — fixed tolerance ladder: one value per generation, non‑increasing, length(εs) == T. Generation t runs at εs[t], so the first entry is the tolerance of the prior sample. This is the historical form — Toni et al. (2009) and Beaumont et al. (2009) both take ε₁ > … > ε_T as input. When given, ε0 is ignored
  • schedule — adaptive tolerance instead: any callable (state, t) -> ε_t, e.g. QuantileSchedule (the default) or a closure. Only generations t ≥ 2 consult it
  • ε0 — tolerance accepting generation 1 in schedule mode; the default Inf makes generation 1 a plain prior sample
  • kernel_rule — scaling rule applied to the population covariance, see scaling_factor: :beaumont (×2, PMC's usual choice), :rosenthal (2.38²/d), :unit (×1) or a literal Real factor
  • M, base_seed, Tθ, max_attempts, checkpoint_dir — as for run_smc

run_pmc! is the state‑based driver, mirroring run_smc!; it runs generation 1 if state.gen == 0 and then advances to generation T, which is also how you resume.

Example

state = run_pmc(cfg, s_obs; N = 1000, T = 5, εs = [4.0, 2.0, 1.0, 0.6, 0.4])
state = run_pmc(cfg, s_obs; N = 1000, T = 5)          # adaptive quantile ladder
state.ess                                             # true ESS of the final population

The cost of choice 2 is weight degeneracy: without resampling the ESS can drift down across generations, which PMC compensates for by re‑estimating Σ_t from the weighted population. Watch state.ess, or compare engines directly with bench/compare_engines.jl.

SequentialABC.run_smc! — Method
run_smc!(state::ABCSMCState, summary_obs;
         T::Int, schedule, M::Int=1, max_attempts::Int=10_000,
         adaptive::Union{Nothing,AdaptiveDistanceConfig}=nothing,
         checkpoint_dir::Union{Nothing,AbstractString}=nothing)

Run ABC‑SMC for T generations with adaptive tolerance schedule.

schedule should be a callable (state, t, distances) -> ε_t. The 2‑arg form (state, t) is preserved for backward compatibility and uses state.dists. Built-in schedules:

  • FixedSchedule — ignores distances, returns εs[t].
  • QuantileSchedule — uses distances (non‑adaptive: state.dists; adaptive: state.adaptive.epsilon_selection_distances). For adaptive mode, the recomputed distances are not bounded by the previous tolerance, so the min(ε_new, ε_cap) guard in epsilon_quantile is load-bearing, not just belt-and-braces.

Required adaptive lifecycle — preparation runs before each upcoming generation and stops after the final requested one:

  1. run generation 1 with unit weights and ε0;
  2. before generation t (2 ≤ t ≤ T), exactly once: a. estimate weights_t from generation t-1 accepted summaries; b. recompute generation t-1 acceptance distances under weights_t; c. derive ε_t from those recomputed distances (the schedule); d. freeze weights_t, ε_t, and gen_applied = t; e. run generation t — weights and ε never change mid-generation;
  3. after generation T, stop: no weights_{T+1} is estimated and the schedule is never called for generation T+1.

On checkpoint resume, the boundary for the upcoming generation runs exactly once (guarded by gen_applied < t). After generation T completes, state.dists / state.ε describe generation T, and the adaptive fields (weights, gen_applied, epsilon_selection_distances, epsilon) describe generation gen_applied == T — never a prepared-but-unrun next generation. state.dists is never overwritten by recomputation.

Resuming a checkpointed adaptive run re-supplies the same adaptive config; the runtime state itself (key order, weights, distances, ε) comes from the checkpoint. Attempting to resume a state that carries adaptive runtime state without passing adaptive throws ArgumentError (the error path is enforced in run_smc!). AdaptiveDistanceConfig(NoAdaptation()) normalizes to the ordinary non-adaptive path — no adaptive state is allocated or checkpointed.

If checkpoint_dir is given, an atomic checkpoint is written after initialization and after every completed generation (state_gen_XXX.jls). Restart by loading with load_latest_state(checkpoint_dir, cfg) and calling run_smc! again with the same directory — the run resumes from state.gen + 1.

SequentialABC.run_smc — Method
run_smc(cfg::ABCSMCConfig, summary_obs; N, T, schedule = QuantileSchedule(0.5),
        ε0 = Inf, M = 1, base_seed = 1, Tθ = nothing, max_attempts = 10_000,
        checkpoint_dir = nothing) -> ABCSMCState

One‑call ABC‑SMC: build the state, generate generation 1 from the prior and advance to generation T, returning the final ABCSMCState. This is the counterpart of run_mcmc, which has the same (config, summary_obs; kwargs…) shape — no manual make_state / initialize! / run_smc! bookkeeping.

Keywords:

  • N::Int — population size
  • T::Int — total generations, including generation 1
  • schedule — callable (state, t) -> ε_t; only generations t ≥ 2 consult it. See QuantileSchedule and FixedSchedule; any function of (state, t) works. For adaptive mode, the schedule receives state.adaptive.epsilon_selection_distances (not state.dists) — see QuantileSchedule for monotonicity notes (the ε_cap/min guard is load-bearing when distances are recomputed under new weights).
  • ε0 — tolerance used to accept generation 1. The default Inf accepts the first prior draw for every particle, so generation 1 is a plain prior sample and the schedule sets the real tolerance from generation 2 on; the state then keeps ε = Inf if T == 1. Pass a finite value to start from a tighter, pre‑filtered set instead
  • M::Int — simulator replicates per particle (summaries are averaged). M = 1 skips averaging entirely: the sole replicate is used unchanged — the identical object, with integer-valued summaries staying Int and NamedTuple summaries accepted as-is (see the internal mean_summary source comment for the full type/identity contract)
  • base_seed — base seed; the same arguments replay an identical run
  • Tθ — parameter type returned by cfg.sample_prior. nothing (default) infers it by drawing one prior sample with a throwaway RNG and discarding the value; pass the type to skip that draw
  • max_attempts — attempts allowed per particle before erroring
  • adaptive — an AdaptiveDistanceConfig enabling adaptive inverse‑distance scaling (estimator, initializer, numerical policy); nothing (default) keeps the plain distance. NoAdaptation inside a config normalizes to the plain, non-adaptive path. The configuration is immutable and must be re-supplied when resuming a checkpointed adaptive run; attempting to resume an adaptive state without adaptive throws ArgumentError (see run_smc!).
  • checkpoint_dir — if given, an atomic checkpoint is written after generation 1 and after every completed generation. Resume with load_latest_state plus run_smc! — calling run_smc again would restart from scratch

Example

state = run_smc(cfg, s_obs; N = 1000, T = 10)
state = run_smc(cfg, s_obs; N = 1000, T = 4,
                schedule = FixedSchedule([4.0, 2.0, 1.0, 0.5]))

Unified inference entrypoint

When the engine is chosen at run time — a config file, a job-array variable, a --engine flag — run_inference is a named forwarder to the three entrypoints above:

engine = Symbol(get(ENV, "ABC_ENGINE", "smc"))     # :smc | :mcmc | :pmc

result = run_inference(engine, cfg, s_obs; N = 1000, T = 5, base_seed = 2026)
symbolentrypointresult typekeywords it accepts
:smcrun_smcABCSMCStateN, T, schedule, ε0, M, base_seed, adaptive, checkpoint_dir
:mcmcrun_mcmcABCMCMCChainn_samples, ε, thin, M, base_seed
:pmcrun_pmcABCSMCStateN, T, εs, schedule, kernel_rule, M, base_seed

adaptive (an AdaptiveDistanceConfig) is forwarded by :smc only. Each engine validates its own keywords — forwarding does not add engine support.

SequentialABC.evaluation_seed — Function
evaluation_seed(
    method::Symbol,
    generation::Integer,
    particle::Integer,
    proposal::Integer,
    attempt::Integer,
    replicate::Integer,
    base_seed::UInt64,
) -> UInt64

Derive a per-evaluation seed from the complete evaluation identity using the versioned EVALUATION_SEED_SCHEMA_VERSION encoding.

Canonical byte stream (schema 1), in order:

  1. EVALUATION_SEED_SCHEMA_VERSION as 8 little-endian bytes;
  2. UTF-8 byte length of String(method) as 8 little-endian bytes;
  3. UTF-8 bytes of String(method);
  4. generation, particle, proposal, attempt, replicate, and base_seed, each as 8 little-endian bytes.

The bytes are folded with FNV-1a 64-bit and finalized with the SplitMix64 avalanche. The derivation is deterministic, portable, and independent of Julia hash().

Inputs are validated: method must be a nonempty Symbol; the five indices must be ≥ 1 and representable as Int64; and base_seed is a UInt64. UInt64(0) is a valid seed value; there is no reserved zero sentinel.

This is not a replacement for make_particle_seed. The legacy make_particle_seed stream is preserved bit-for-bit for existing inference runs; evaluation_seed is the seed source for the new evaluation contract only.

source
SequentialABC.EVALUATION_SEED_SCHEMA_VERSION — Constant
EVALUATION_SEED_SCHEMA_VERSION::UInt64

Version of the seed derivation encoding used by evaluation_seed.

Schema 1 mixes the complete evaluation identity (method, generation, particle, proposal, attempt, replicate, base_seed) into a UInt64 using an explicit, stable byte encoding. Changing any identity field changes the derived seed within the tested domain. This is deliberately not Julia's hash() and is not intended as a cryptographic or content-addressable identifier; it is a persistent, deterministic, per-evaluation seed.

The legacy make_particle_seed stream is a separate, explicitly named legacy schema. It is preserved unchanged and remains the seed source for the existing SMC/PMC/MCMC engines.

SequentialABC.retry_with_limit — Function
retry_with_limit(
    policy::FailurePolicy,
    ctx::EvaluationContext,
    result::EvaluationResult,
    max_retries::Int,
) -> Tuple{Symbol,EvaluationContext}

Apply a failure policy once and enforce a bounded retry budget.

This helper computes policy actions only. It never runs a simulator and never creates or modifies an EvaluationResult; the structured failure in result remains owned by the caller.

Semantics:

  • max_retries is the maximum number of retries allowed after the original attempt. Attempts are counted by ctx.attempt, which starts at 1, so the helper aborts when ctx.attempt - 1 >= max_retries.
  • If the policy returns :retry and budget remains, the returned context has attempt + 1 and a seed re-derived by evaluation_seed for the new attempt. The caller performs the next simulation with that context.
  • If the policy returns :retry and the budget is exhausted, :abort is returned with the current context unchanged.
  • :reject and :abort are returned with the current context unchanged.
  • Any other policy action throws ArgumentError.

The function performs exactly one policy call per invocation. It cannot loop indefinitely, regardless of the policy's return value.

SequentialABC.evaluate — Function
evaluate(
    simulator,

    context::EvaluationContext;
    provenance::NamedTuple=NamedTuple(),
    capture_stacktrace::Bool=true,

Additive adapter around existing simulator execution. Invokes the simulator using context.seed, measures wall time, captures successful summaries, classifies nonfinite summaries, and converts simulator exceptions into structured EvaluationFailure values.

SequentialABC.NativeRunStore — Type
NativeRunStore <: AbstractRunStore

File-backed run store.

A native store keeps the committed history of a run in a directory tree and reconstructs its visible state from the committed files when it is opened. The store never keeps the authoritative history in process memory: only the pending generation of the current session is held in memory, and it is discarded when the session ends without publishing it.

Fields:

  • root::String — absolute path of the run directory
  • metadata::RunMetadata — validated identity of the run
  • mode::Symbol — :read or :write
  • pending_generation::Union{Nothing,Int64} — the generation being written
  • pending_population::Union{Nothing,PopulationRecord} — its population
  • pending_evaluations::Vector{EvaluationRecord} — its evaluations
  • pending_keys::Set{EvaluationKey} — their identities
  • lease_path::Union{Nothing,String} — the writer lease this store owns
  • closed::Bool — whether the store was closed
  • fault — internal fault injector; nothing in production

Open a store with open_run and close it with close_run!. A store in write mode owns the writer lease for the whole session and releases it only when it is closed; a store in read mode never takes the lease and can read committed generations while another writer is active.

The native format is Julia-native, trusted-input only, and not portable. A run store records history; it never resumes inference.

Checkpointing

A checkpoint is the exact sampler-restart authority: it holds the current sampler state, it is written with Julia's Serialization (native, trusted input), and the caller reattaches a compatible cfg on load. It carries no checksum, no integrity manifest, and no completion marker — for the queryable, integrity-checked run history, see the run store.

SequentialABC.save_checkpoint — Method
save_checkpoint(state::ABCSMCState, dir::AbstractString) -> String

Write the sampler state to dir/state_gen_XXX.jls with a temporary file and a rename.

Only data is serialized (θ, w, summaries, ε, gen, ess, seeds, counters, plus adaptive state when present) — never cfg and its closures. The configuration is therefore reattached by the caller: reload with a compatible cfg via load_latest_state. The stored data itself is written with Julia's Serialization, so the file is native to the Julia version that wrote it and to the types it holds. It is not a version-independent or cross-language format, and a checkpoint written before a change to the particle or summary types has to be migrated explicitly.

A schema_version tag is written with every checkpoint: 1 for non-adaptive payloads, 2 for adaptive payloads (see load_checkpoint for the compatibility matrix). New code reads legacy (untagged, schema 0), schema-1 and schema-2 checkpoints; old code cannot read schema-2 adaptive checkpoints (unsupported — it ignores the tag and would silently resume without the adaptive state).

Write protocol: the payload is written to a .tmp file first and then renamed into place. On POSIX that rename is atomic within one filesystem, so a reader never observes a partially published checkpoint, and a process killed before the rename leaves the canonical file untouched and at worst a stale .tmp file, which the loader ignores. The guarantee is per filesystem: a move across filesystems is a copy, filesystems without an atomic rename do not provide it, and power loss during the write is not covered. A checkpoint carries no checksum, no integrity manifest, and no completion marker, and it is not authenticated: a damaged file is detected when it fails to deserialize, not before. The run store is the mechanism that adds digests, manifests, and completion markers — to the run history, not to the restart state.
