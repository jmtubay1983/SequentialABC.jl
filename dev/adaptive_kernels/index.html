Adaptive kernels

ABC‑SMC and ABC‑MCMC both move particles with a Gaussian random walk (\theta' \sim \mathcal{N}(\theta, \Sigma)). The perturbation kernel of the sampler and the proposal of the chain are the same object, so both engines benefit from the same machinery — and both suffer from the same hand‑tuning problem:

  • (\Sigma) too small — the population barely moves. Particles stay near‑duplicates of their ancestors, the accepted region is never explored, and the tolerance stops shrinking.
  • (\Sigma) too large — almost every proposal lands outside the acceptance region. Simulations are wasted on redraws, and the importance weights become extremely uneven.

The standard remedy is to estimate (\Sigma) from the current population and update it as the run progresses. AdaptiveKernel does exactly that, using only LinearAlgebra, Statistics and Random.

Estimating a covariance

estimate_covariance accepts either an (N \times d) matrix or a length‑(N) vector of parameter vectors — exactly the layout of ABCSMCState.θ — together with optional importance weights:

Σ̂ = estimate_covariance(state.θ, state.w)          # weighted, d × d
Σ̂ = estimate_covariance(matrix_of_samples)         # uniform weights

Two details matter for stability:

  • Reliability weights. The normalisation is (1 - \sumi wi^2) with the weights normalised to sum to one, which reduces to the usual unbiased (N - 1) denominator for uniform weights.
  • Shrinkage. The estimate is pulled towards isotropy, (\tilde\Sigma = (1-\lambda)\hat\Sigma + \lambda\,(\operatorname{tr}\hat\Sigma/d)I), with (\lambda) = shrink (default 1e-6). A positive shrink makes the result positive definite even for a rank‑deficient population ((N \le d), duplicate particles, …). That is what keeps the Cholesky factorisation in the perturbation step from failing. Fully degenerate inputs fall back to shrink · I.

Because the estimator is weighted, it also works on the importance‑weighted population, not just on a resampled one.

Scaling rules

The estimated covariance is not used directly: it is multiplied by a rule of thumb factor, Σ = scaling_factor(d; rule) · Σ̂.

rulefactorintended use
:rosenthal (alias :gelman)(2.38^2 / d)classic optimal random‑walk scaling for MCMC (Gelman, Roberts & Gilks 1996)
:beaumont (alias :abc)(2)twice the population covariance — the usual ABC‑SMC perturbation kernel, which must compensate for the resampling step (Beaumont et al. 2009)
:unit / :none(1)proposal covariance = estimated covariance
a Realthe valueany custom factor

The estimate itself is anisotropic — every dimension keeps its own variance and the correlations are preserved — so per‑dimension scaling comes for free.

Online (streaming) estimation

estimate_covariance needs the whole population in memory. OnlineCovEstimator produces the same estimate from one particle at a time, with (O(d^2)) memory, using Welford's algorithm for weighted populations:

est = OnlineCovEstimator(d)          # shrink defaults to 1e-6
for (θ, w) in zip(population, weights)
    update!(est, θ, w)               # incremental, one particle at a time
end
Σ̂ = cov(est)                         # == estimate_covariance(population, weights)
reset!(est)                          # reuse for the next generation

The mean is updated incrementally and the second moment uses both the old and the new mean, so there is no (E[\theta\theta^\top] - \mu\mu^\top) cancellation. cov applies the same shrinkage as the batch estimator and then an eigenvalue floor (\lambda_{\min} = \max(\texttt{shrink}, (\operatorname{tr}\Sigma)/d \cdot 10^{-8}, \epsilon)), which makes the returned matrix positive definite unconditionally — even after a single sample. A population with fewer than two effective samples (or exactly coincident particles) reports a zero‑variance raw estimate, which the floor regularises and commit! refuses to adopt.

Adaptive ABC-SMC

ABCSMCConfig is immutable, so the way to install a new covariance is to rebuild the config with with_covariance:

kernel = AdaptiveKernel([0.5 0.0; 0.0 0.5]; rule = :beaumont)

state = make_state(cfg, Vector{Float64}, 500, 4.0, 42)
initialize!(state, s_obs)

for t in 2:T
    update!(kernel, state.θ, state.w)                # Σ ← 2 · Cov(population)
    state.cfg = with_covariance(state.cfg, kernel)   # type-stable assignment
    run_generation!(state, s_obs; ε = epsilon_quantile(state, 0.5))
end

ABCSMCState is mutable and with_covariance preserves the concrete configuration type, so the reassignment is type‑stable. kernel.n_updates counts how many adaptations were applied, and a degenerate population is ignored rather than adopted (a zero‑variance kernel would freeze the sampler).

The streaming form trades the population copy for an accumulator:

for i in eachindex(state.θ)
    update!(kernel, state.θ[i], state.w[i])   # accumulate, O(d²) memory
end
commit!(kernel)                               # adopt Σ, reset the accumulator
state.cfg = with_covariance(state.cfg, kernel)

Committing at the generation boundary is deliberate: every importance weight of a generation is computed with that generation's kernel, so a (\Sigma) that changed halfway through would make the weights inconsistent. The accumulation is streaming; the adoption is per generation. Passing an OnlineCovEstimator directly — update!(kernel, est) — copies it in and commits immediately.

Adaptive ABC-MCMC

The chain's proposal is cfg.Σ, so the adapted covariance is installed the same way:

cfg_adapted = with_covariance(cfg, kernel)
chain = run_mcmc(cfg_adapted, s_obs; n_samples = 5000, ε = ε_final, base_seed = 1)
acceptance_rate(chain)

Sampling from the kernel directly uses the same naming as the built‑in GaussianKernel: perturb(kernel, θ, rng) draws a proposal (internal helper), and calling the kernel — kernel(θ_new, θ_old) — returns the proposal log density. The Gaussian random walk is symmetric, so that density is unchanged by swapping its arguments; a pre‑run adaptation (estimate once, then freeze) is therefore a valid Metropolis–Hastings proposal. Adapting the covariance continuously inside a single chain requires vanishing adaptation to preserve the stationary distribution and is deliberately out of scope here.

Example

Two runnable scripts:

julia --project=. examples/adaptive_kernel_example.jl   # fixed vs adapted Σ
julia --project=. examples/online_kernel_example.jl    # streaming vs batch adaptation

The first runs the same ABC‑SMC problem twice from a deliberately badly scaled (\Sigma_0), once fixed and once adapted, and then reuses the adapted covariance as the ABC‑MCMC proposal. The second shows that the streaming estimator matches the batch estimate to machine precision and runs the same SMC problem with both update forms.

API

SequentialABC.AdaptiveKernel — Type
AdaptiveKernel(Σ0; shrink = 1e-6, rule = :rosenthal)

Gaussian random‑walk kernel θ' ~ 𝒩(θ, Σ) whose covariance is re‑estimated from the particle population as a run progresses.

Batch update — hand over the whole population:

update!(kernel, population, weights)             # Σ ← scaling_factor(d; rule) · estimate_covariance(…)
state.cfg = with_covariance(state.cfg, kernel)   # ABC-SMC: pick up the new Σ

Streaming update — feed particles as they are generated, which needs O(d²) memory instead of keeping the population, then commit once per generation:

for (θ, w) in zip(state.θ, state.w)
    update!(kernel, θ, w)      # accumulates into an internal OnlineCovEstimator
end
commit!(kernel)                # adopt Σ, reset the accumulator

Committing at the generation boundary is deliberate: the SMC importance weights of a generation are computed with the kernel of that generation, so a Σ that changed halfway through would make the weights inconsistent. Accumulate online, commit once, then perturb.

Fields:

  • Σ::Matrix{Float64} — current proposal covariance
  • Σ_inv::Matrix{Float64} — its inverse, refreshed by the update
  • logdetΣ::Float64 — log det Σ, refreshed by the update
  • shrink::Float64 — shrinkage applied to every estimate
  • rule::Union{Symbol,Float64} — scaling rule, see scaling_factor
  • n_updates::Int — how many covariance updates were applied
  • est::OnlineCovEstimator — accumulator for per‑particle updates

Σ0 must be symmetric positive definite. Sampling from the kernel mirrors GaussianKernel: perturb(kernel, θ, rng) draws a proposal and calling the kernel, kernel(θ_new, θ_old), evaluates the proposal log density.

SequentialABC.OnlineCovEstimator — Type
OnlineCovEstimator(d::Integer; shrink = 1e-6)

Streaming weighted covariance estimator — Welford's algorithm for a d‑dimensional weighted population, with O(d²) memory and no need to keep the samples.

est = OnlineCovEstimator(2)
for (θ, w) in zip(population, weights)
    update!(est, θ, w)          # incremental, one particle at a time
end
Σ̂ = cov(est)                    # the same estimate `estimate_covariance` would give

The weighted mean/covariance pair is updated as

W  += w;  W2 += w²
μ  += (w / W) (x − μ)
M2 += w (x − μ_old)(x − μ_new)ᵀ        # Welford, uses the updated mean
Σ   = M2 · W / (W² − W2)

so the denominator is the reliability normaliser 1 − Σw̃ᵢ² (w̃ normalised to sum to one) written in unnormalised weights; for uniform weights it is the unbiased N − 1 denominator, exactly as in estimate_covariance.

Numerical guards:

  • the mean is updated incrementally and the second moment uses both the old and the new mean, which avoids the cancellation of a naive E[x xᵀ] − μμᵀ;
  • cov shrinks towards isotropy (λ = shrink) and then applies an eigenvalue floor λ_min = max(shrink, (tr Σ)/d · 10⁻⁸, eps()), so the returned matrix is always symmetric positive definite — even after a single sample;
  • a population with fewer than two effective samples (or exactly coincident samples) reports a zero‑variance raw estimate, which cov floors and update!(kernel, …)/commit! refuse to adopt.

Fields: d, μ::Vector{Float64}, M2::Matrix{Float64}, W::Float64 (sum of weights), W2::Float64 (sum of squared weights), shrink::Float64, n::Int (number of particles seen). Use reset! to clear the state.

SequentialABC.update! — Function
update!(est::OnlineCovEstimator, θ, w = 1.0) -> OnlineCovEstimator

Fold one particle θ with weight w into the streaming estimate. w = 0 is a no‑op; negative or non‑finite weights raise an ArgumentError, and a θ of the wrong dimension raises a DimensionMismatch. Returns the estimator so calls can be chained.

source
update!(kernel::AdaptiveKernel, samples, weights = nothing) -> AdaptiveKernel
update!(kernel::AdaptiveKernel, θ, w = 1.0) -> AdaptiveKernel
update!(kernel::AdaptiveKernel, est::OnlineCovEstimator) -> AdaptiveKernel

Re‑estimate the kernel covariance from a particle population, then refresh the cached Σ_inv / logdetΣ:

Σ ← scaling_factor(d; kernel.rule) · estimate_covariance(samples, weights; shrink = kernel.shrink)

Three forms:

  • samples is a whole population — an N × d matrix or the Vector{<:AbstractVector} layout of ABCSMCState.θ — applied immediately;
  • a single parameter vector (AbstractVector{<:Real}) with weight w is accumulated into the kernel's OnlineCovEstimator; call commit! once the generation is complete to adopt it;
  • an OnlineCovEstimator is copied in and committed immediately (convenience for a caller that maintains its own estimator).

A degenerate population (zero estimated variance — every particle identical) is ignored: the kernel keeps its current covariance instead of collapsing to a zero‑variance proposal that would freeze the sampler, and n_updates is left unchanged. A population of the wrong dimension raises a DimensionMismatch. Returns the kernel, so the call can be chained.

source
SequentialABC.commit! — Function
commit!(kernel::AdaptiveKernel) -> AdaptiveKernel

Adopt the covariance accumulated by per‑particle update!(kernel, θ, w) calls (through the kernel's internal OnlineCovEstimator), refresh Σ_inv / logdetΣ, increment n_updates and reset! the accumulator.

A degenerate accumulation — fewer than two effective samples, or a population of exactly coincident particles — is ignored (the current Σ is kept and n_updates is not incremented), so a frozen population cannot collapse the kernel to zero variance. The accumulator is reset either way.

source
SequentialABC.reset! — Function
reset!(est::OnlineCovEstimator) -> OnlineCovEstimator

Clear the accumulated state (μ, M2, W, W2, n) so the estimator can be reused for the next generation. The dimension and shrinkage are kept.

Statistics.cov — Function
cov(est::OnlineCovEstimator; shrink = est.shrink) -> Matrix{Float64}

Current covariance estimate: the reliability‑weighted covariance, shrunk towards isotropy by shrink, with an eigenvalue floor of max(shrink, (tr Σ)/d · 10⁻⁸, eps()) so the result is always positive definite. An empty or single‑sample estimator therefore returns a small isotropic matrix rather than a singular one.

cov(kernel::AdaptiveKernel) -> Matrix{Float64}

The covariance the kernel is currently proposing with (a copy, so mutating the result cannot corrupt the kernel).

SequentialABC.estimate_covariance — Function
estimate_covariance(samples, weights = nothing; shrink = 1e-6) -> Matrix{Float64}

Weighted covariance of a particle population, symmetrised and shrunk towards isotropy. This is the batch estimator: it takes the whole population at once. For per‑particle streaming updates use OnlineCovEstimator; the two agree to floating‑point precision.

  • samples — an N × d matrix, or a length‑N vector of parameter vectors (exactly the layout of ABCSMCState.θ)
  • weights — importance weights; nothing means uniform
  • shrink — shrinkage intensity λ ∈ [0, 1] towards (tr Σ̂ / d) I

The normalisation uses reliability weights, 1 - Σᵢ wᵢ² with the weights normalised to sum to one, which reduces to the unbiased N - 1 denominator for uniform weights.

Shrinkage makes the estimate positive definite even for a rank‑deficient population (N ≤ d, duplicate particles, …), which is what keeps the Cholesky factorisation of the perturbation step from failing. Fully degenerate inputs (a single sample, or every sample identical) fall back to shrink · I; the result is always symmetric. update! detects that fallback and refuses to adopt it, so a frozen population cannot collapse the kernel to zero variance.

SequentialABC.with_covariance — Function
with_covariance(cfg::ABCSMCConfig, Σ) -> ABCSMCConfig
with_covariance(cfg::ABCSMCConfig, kernel::AdaptiveKernel) -> ABCSMCConfig

Copy cfg with a new perturbation covariance Σ (recomputing Σ_inv and logdetΣ).

ABCSMCConfig is immutable, so this is the integration point for adaptive kernels: after update!(kernel, state.θ, state.w), assign

state.cfg = with_covariance(state.cfg, kernel)

and the next run_generation! perturbs, weights and resamples with the adapted covariance. ABCSMCState is mutable and state.cfg keeps the same concrete type, so the assignment is type‑stable. The streaming form is identical, with commit!(kernel) standing in for the update!: state.cfg = with_covariance(state.cfg, commit!(kernel)) after feeding the particles one at a time.
