ABC-MCMC

ABC-SMC walks a population through a sequence of tolerances; ABC-MCMC (Marjoram, Molitor, Plagnol & Tavaré 2003) instead runs a single Markov chain whose stationary distribution is the ABC posterior

[ \pi\epsilon(\theta \mid s{\text{obs}}) \;\propto\; \pi(\theta)\, \mathbf{1}!\left[d\big(s(\theta), s_{\text{obs}}\big) \le \epsilon\right]. ]

At a fixed tolerance, a proposal (\theta' \sim \mathcal{N}(\theta, \Sigma)) is accepted when

  1. the simulated summary is close enough, (d(s(\theta'), s_{\text{obs}}) \le \epsilon), and
  2. a Metropolis–Hastings test with the prior ratio passes, (u < \min!\big(1, \exp(\log \pi(\theta') - \log \pi(\theta))\big)).

The Gaussian random walk is symmetric, so the proposal densities cancel and only the prior ratio is left. Compared with ABC-SMC, ABC-MCMC needs no tolerance schedule and no resampling — but the samples are autocorrelated, and a poor starting point is expensive because the chain stays there.

Running a chain

using SequentialABC, Distributions, Random

prior(θ) = logpdf(Normal(0.0, 2.0), θ[1])
sample_prior(rng) = [2.0 * randn(rng)]

simulator = ContinuousSimulator(model_builder = θ -> θ,
                                evolve = (θ, rng) -> θ[1] + 0.3 * randn(rng),
                                summary = identity)

cfg = ABCSMCConfig(prior, sample_prior, identity,
                   (s, so) -> abs(s - so), GaussianKernel(), [0.05;;], simulator)

chain = run_mcmc(cfg, s_obs; n_samples = 2000, ε = 0.3, base_seed = 2024)

acceptance_rate(chain)   # ≈ expected MH acceptance rate
chain.state.θ            # the samples

The chain is initialised by drawing from the prior until d ≤ ε, then advanced for n_samples * thin iterations. One sample is stored per thin iterations, plus the initial state, so length(chain) == n_samples + 1.

Determinism

Every proposal, simulation and accept/reject draw uses a MersenneTwister seeded from make_particle_seed(1, iteration, 1, role, base_seed), with distinct role sentinels for the three streams. The same configuration and base_seed therefore replay a bit-identical chain, on any machine or Slurm node. The uniform draw for the acceptance test is taken unconditionally, even when the distance test already fails, so the random stream never depends on the data.

Reusing the rest of the package

The chain stores its samples in an ABCSMCState with uniform weights — the same container an ABC-SMC run produces. Everything that consumes a result therefore works on MCMC output unchanged:

plot_marginals(chain.state; labels = ["a", "b"])                  # figures
adjusted_posterior(chain.state; observed_summary = s_obs)         # correction
save_checkpoint(chain.state, "chain.jls")                         # checkpoints

Example

A runnable two-parameter demonstration lives in examples/two_param_mcmc.jl:

julia --project=. examples/two_param_mcmc.jl

It runs a chain on a linear-regression summary, reports the posterior means against the true coefficients, verifies reproducibility, and applies the regression correction to the chain.

References

  • Marjoram, P., Molitor, J., Plagnol, V., & Tavaré, S. (2003). Markov chain Monte Carlo without likelihoods. PNAS, 100(26), 15324–15328.

API

SequentialABC.run_mcmc — Function
run_mcmc(cfg::ABCSMCConfig, summary_obs; n_samples, ε, thin=1, M=1,
         base_seed=1, max_attempts=10_000) -> ABCMCMCChain

Run an ABC‑MCMC chain (Marjoram et al. 2003) of n_samples * thin iterations and return the ABCMCMCChain.

  • n_samples::Int — number of snapshots to store (plus the initial state)
  • ε::Float64 — ABC tolerance; proposals with d(s', s_obs) > ε are rejected
  • thin::Int — keep one sample every thin iterations (reduces autocorrelation)
  • M::Int — simulator replicates per iteration (summaries are averaged)
  • base_seed::Int — base seed; the same config and seed replay an identical chain
  • max_attempts::Int — attempts allowed when searching for a feasible start point

The chain is initialised from a prior draw that already satisfies d ≤ ε and then follows the random‑walk Metropolis rule of abc_mcmc_accept at fixed tolerance ε. Accepted particles are returned in an ABCSMCState with uniform weights (length n_samples + 1).

SequentialABC.ABCMCMCChain — Type
ABCMCMCChain

Output of run_mcmc: a Markov chain whose stationary distribution is the ABC posterior π_ε(θ | s_obs).

Fields:

  • state::ABCSMCState — stored samples (the initial state plus one snapshot every thin iterations) with uniform weights. This is the same container an ABC‑SMC run produces, so downstream tooling works unchanged.
  • accepted::Vector{Bool} — accept/reject decision of every chain iteration
  • ε::Float64 — tolerance the chain was run at
  • Σ::Matrix{Float64} — random‑walk proposal covariance
  • base_seed::Int — base seed the chain was run with
  • n_simulations::Int — total number of simulator calls (diagnostic)

Use length(chain) for the number of stored samples and acceptance_rate for the acceptance diagnostic.

SequentialABC.acceptance_rate — Function
acceptance_rate(chain::ABCMCMCChain) -> Float64

Fraction of proposed moves that were accepted — the first diagnostic of an ABC‑MCMC run. Very low rates mean the proposal covariance Σ is too large for the tolerance ε; rates close to 1 mean Σ is too small for the chain to explore the posterior.

source
SequentialABC.abc_mcmc_accept — Function
abc_mcmc_accept(logprior_prop, logprior_cur, d_prop, ε, u;
                log_proposal_ratio=0.0) -> Bool

Metropolis–Hastings acceptance test for ABC‑MCMC, exposed as a pure function so the sampling logic can be tested in isolation:

  1. d_prop > ε ⇒ reject — the proposal falls outside the ABC acceptance region, whatever the prior ratio says;
  2. log α = (logprior_prop − logprior_cur) + log_proposal_ratio; reject when log α is NaN (e.g. both prior densities are -Inf, i.e. outside support);
  3. otherwise accept with probability min(1, exp(log α)), decided by the uniform draw u ∈ [0, 1).

u must always be drawn by the caller — even when the distance test already fails — so the random stream never depends on the data.

source
SequentialABC.mcmc_propose — Function
mcmc_propose(cfg::ABCSMCConfig, θ, rng::AbstractRNG) -> Vector{Float64}

Draw a proposal θ' ~ 𝒩(θ, Σ) from the random‑walk proposal, where Σ is cfg.Σ. Thin wrapper around the ABC‑SMC perturbation kernel, so an ABC‑MCMC and an ABC‑SMC run move particles identically given the same seed and covariance.

source
SequentialABC.mcmc_log_proposal — Function
mcmc_log_proposal(cfg::ABCSMCConfig, θ_new, θ_old) -> Float64

Log density log K(θ_new | θ_old) of the random‑walk proposal, including the normalising constant.

The Gaussian random walk is symmetric, mcmc_log_proposal(cfg, a, b) == mcmc_log_proposal(cfg, b, a), which is exactly what reduces the Metropolis–Hastings ratio to the prior ratio.
