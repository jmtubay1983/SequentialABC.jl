Recipes

Every engine, schedule, kernel and summary in this package has a documented "right starting value" — but they live on different pages. This page collects them into three functions that hand those defaults back ready to drop into a config or an engine call:

You writeYou get
default_schedule(:smc)the adaptive median-quantile schedule both SMC and PMC default to
default_schedule(T; ε0, εT)the geometric tolerance ladder of the engine-comparison benchmarks
default_kernel_scaling(θs; engine)Σ₀ from a pilot population: 2 · Ĉov(θ) for SMC/PMC, 2.38²/d · Ĉov(θ) for MCMC
preset_summaries(:moments)a ready-made summary for the shape of your simulator output

Nothing here is new machinery. Each recipe composes primitives that are documented and tested on their own (QuantileSchedule, FixedSchedule, estimate_covariance, adaptive_scale, FunctionSummary, CompositeSummary), so a recommendation can always be read back to the underlying knob — and swapped out piecewise.

One run, all three

using SequentialABC, Distributions, Random

# What the simulator reports: the coordinates under stable names.
base = preset_summaries(:vector; names = (:a, :b))
sim  = ContinuousSimulator(
    model_builder = θ -> θ,
    evolve = (θ, rng) -> θ .+ randn(rng, 2),
    summary = raw -> namedtuple_to_vector(compute_summary(base, raw)),
)

# What the particles move with: 2 × the pilot covariance.
rng   = MersenneTwister(2026)
pilot = [sample_prior(rng) for _ in 1:200]
Σ0    = default_kernel_scaling(pilot)

cfg = ABCSMCConfig(prior, sample_prior, identity, l2_distance,
                   GaussianKernel(), Σ0, sim)
s_obs = [1.0, -1.0]                            # in summary_keys(base) order

state = run_inference(:smc, cfg, s_obs;
                      N = 1000, T = 6, schedule = default_schedule(:smc),
                      base_seed = 2026)

The preset names the summary keys, l2_distance is the distance those keys flow into, the kernel recipe seeds the perturbation, and the schedule recipe retightens the tolerance each generation. Every piece stays an ordinary object: base can be composed with further summaries, Σ0 can be replaced by any matrix, and the schedule is any callable (state, t) -> ε.

Schedules

default_schedule(engine) returns the adaptive rule — QuantileSchedule(q) with the house default q = 0.5, i.e. each generation runs at the median of the previous generation's accepted distances. It is exactly what run_smc and run_pmc already default to; the recipe exists so the recommendation has a name and lives in one place.

schedule = default_schedule(:smc)               # QuantileSchedule(0.5)
schedule = default_schedule(:smc; q = 0.25)     # tighter adaptation

ABC-MCMC is the exception: it runs at a single fixed ε and takes no schedule, so default_schedule(:mcmc) is an error that spells out the actual recipe — calibrate ε from a short adaptive run (see ABC-MCMC):

st    = run_inference(:smc, cfg, s_obs; N = 500, T = 4, base_seed = 1)
ε_cal = epsilon_quantile(st, 0.5)               # the median accepted distance
chain = run_inference(:mcmc, cfg, s_obs; n_samples = 10_000, ε = ε_cal)

With a generation count, the second form builds the prescribed geometric ladder between two tolerances — the schedule the engine-comparison benchmarks run, where every run must see the same ε trajectory and the budget must be known in advance:

ladder = default_schedule(5; ε0 = 4.0, εT = 0.4)
# εs = [4.0, 2.2493, 1.2649, 0.7113, 0.4]        one rung per generation
state  = run_inference(:smc, cfg, s_obs; N = 1000, T = 5,
                       schedule = ladder, ε0 = 4.0)

Generation 1 accepts at the engine's initial tolerance ε0: pass the first rung there so the ladder and the run start together — or leave the default Inf, and generation 1 is a plain prior sample. run_pmc consumes the same ladder through its εs vector, which also sets its starting tolerance:

state = run_inference(:pmc, cfg, s_obs; N = 1000, T = 5, εs = ladder.ε)

Kernel scalings

A fixed perturbation covariance is the classic pain point of ABC — too small and the population cannot move, too large and almost every proposal misses the acceptance region. The standard scaling per engine:

enginescalingrationale
:smc / :pmc2 · Ĉov(θ)twice the population covariance, wide enough to counter resampling (Beaumont et al. 2009); run_pmc re-derives Σ_t every generation anyway
:mcmc2.38²/d · Ĉov(θ)the classic optimal random-walk scaling (Gelman, Roberts & Gilks 1996)
rng   = MersenneTwister(2026)
pilot = [sample_prior(rng) for _ in 1:200]      # prior-predictive pilot
Σ_smc = default_kernel_scaling(pilot)           # :smc is the default engine
Σ_mc  = default_kernel_scaling(pilot; engine = :mcmc)

samples is either an N × d matrix or a length-N vector of parameter vectors — the layout of ABCSMCState.θ — from a prior-predictive pilot or the first generation of a short run. Underneath sits estimate_covariance, which shrinks toward isotropy, so the result stays positive definite even for small or degenerate pilots; weights and shrink forward to it. Without a pilot, default_kernel_scaling(d) falls back to the scaled unit prior, factor · I — only meaningful when the prior is roughly 𝒩(0, I); prefer the samples form as soon as a pilot exists.

The primitives remain available for other rules: call adaptive_scale / scaling_factor with the rule you want (see Adaptive kernels for all rules and the streaming estimator).

Summary presets

preset_summaries(preset) returns a ready summary for the shape of output a simulator actually reports:

presetinputkeys
:scalarone numbername (default :value)
:vectora vector of numbersnames, or :v1, :v2, … via d
:momentsa collection of numbers:count, :mean, :sd
:quantilesa collection of numbersprobs, named by percentage
base = preset_summaries(:vector; names = (:a, :b))
summary_keys(base)                               # [:a, :b]

pop = preset_summaries(:moments)                 # replicates within one θ
compute_summary(pop, [1.0, 2.0, 3.0, 4.0])       # (count = 4, mean = 2.5, sd = 1.291…)

q = preset_summaries(:quantiles; probs = (0.1, 0.9))
summary_keys(q)                                  # [:q10, :q90]

Points worth knowing:

  • Keys are declared, not discovered: :moments always reports exactly :count, :mean, :sd, and :quantiles names keys by percentage — 0.975 becomes :q97_5, 1/20 becomes :q5.
  • Passing a keyword the preset does not use is an error, and duplicate keys are rejected at construction — a typo cannot silently drop a summary from the distance.
  • The result is an ordinary summary object: compose it with more summaries, rescale it with scale, reduce it with pca_reduce, average replicates with aggregate — see Summary statistics for the full framework.

Determinism

The recipes are pure functions of their arguments: the same pilot gives the same Σ₀, the same (T, ε0, εT) the same ladder, the same preset the same keys and values — no RNG anywhere. The pilot itself is a data choice, exactly like s_obs: fix its seed, and the whole run stays reproducible under the engines' existing replay guarantee.

API

SequentialABC.default_schedule — Function
default_schedule(engine::Symbol; q = 0.5) -> QuantileSchedule
default_schedule(T::Integer; ε0, εT) -> FixedSchedule

Recommended tolerance schedule for a workflow, returned as a callable (state, t) -> ε_t ready for the schedule keyword of run_smc / run_pmc:

  • engine = :smc or :pmc — the adaptive q‑quantile rule, QuantileSchedule(q), with the house default q = 0.5 (the median of the previous generation's accepted distances, the Toni et al. (2009) fixed ladder replaced by adaptation). This is exactly what both engines default to; naming it here keeps the recommendation in one place.
  • engine = :mcmc — there is no schedule: ABC‑MCMC runs at a single fixed ε. Calibrate it from a short adaptive run instead, e.g. st = run_smc(cfg, s_obs; N = 500, T = 4); ε = epsilon_quantile(st, 0.5). The error message repeats this recipe.
schedule = default_schedule(:smc)             # QuantileSchedule(0.5)
state    = run_inference(:smc, cfg, s_obs; N = 1000, T = 6, schedule = schedule)

With a generation count, the geometric ladder between two tolerances — the prescribed schedule used by the engine‑comparison benchmarks, where every run must see the same ε trajectory:

schedule = default_schedule(5; ε0 = 4.0, εT = 0.4)
# εs = [4.0, 2.2493, 1.2649, 0.7113, 0.4]     one rung per generation
state    = run_inference(:smc, cfg, s_obs; N = 1000, T = 5,
                         schedule = schedule, ε0 = 4.0)

Generation 1 accepts at the engine's initial tolerance ε0; pass the first rung there so the ladder and the run start together (left at the default Inf, generation 1 is a plain prior sample). run_pmc consumes the same ladder through its εs vector, which also sets its starting tolerance: run_pmc(cfg, s_obs; T = 5, εs = default_schedule(5; ε0 = 4.0, εT = 0.4).ε).

Requires T ≥ 2, 0 < εT ≤ ε0, and finite endpoints. Prefer the adaptive form — it needs no tuning; take the geometric ladder when the ε budget must be known in advance (cost planning, HPC) or held fixed for comparisons.

SequentialABC.default_kernel_scaling — Function
default_kernel_scaling(samples; engine = :smc, weights = nothing, shrink = 1e-6)
default_kernel_scaling(d::Integer; engine = :smc)

Recommended initial perturbation covariance Σ₀ for a config, estimated from a pilot population and scaled by the standard rule for the workflow:

enginescalingrationale
:smc2 · Ĉov(θ)twice the population covariance — the usual ABC‑SMC perturbation kernel (Beaumont et al. 2009), wide enough to counter resampling
:pmc2 · Ĉov(θ)the same rule; run_pmc re‑derives Σ_t every generation anyway, so this only seeds the adaptive kernel
:mcmc2.38²/d · Ĉov(θ)the classic optimal random‑walk scaling (Gelman, Roberts & Gilks 1996)

samples may be an N × d matrix or a length‑N vector of parameter vectors (exactly the layout of ABCSMCState.θ) — take it from a prior‑predictive pilot or from a short uncalibrated run. The estimate underneath is estimate_covariance, which shrinks towards isotropy and therefore stays positive definite even for tiny or degenerate pilots; weights and shrink are forwarded to it.

rng   = MersenneTwister(2026)
pilot = [sample_prior(rng) for _ in 1:200]
Σ0    = default_kernel_scaling(pilot)             # :smc ⇒ 2 × pilot covariance
cfg   = ABCSMCConfig(prior, sample_prior, transform, distance,
                     GaussianKernel(), Σ0, sim)

Without a pilot yet, default_kernel_scaling(d) falls back to the scaled unit prior, factor · I — only meaningful when the prior is roughly 𝒩(0, I); prefer the samples form as soon as a pilot exists.

The primitives stay available for other choices: estimate_covariance for the raw estimate and adaptive_scale / scaling_factor for custom rules (see Adaptive kernels).

SequentialABC.preset_summaries — Function
preset_summaries(preset::Symbol; name = nothing, names = nothing,
                 d = nothing, probs = nothing) -> AbstractSummary

Ready-made summary for the four shapes simulator outputs come in — the object a ContinuousSimulator/AgentsSimulator should put in its summary field (see Summary statistics):

presetinputkeysexample
:scalarone numbername (default :value)(value = 3.5,)
:vectora vector of numbersnames, or :v1, :v2, … via d(a = 10.0, b = 20.0)
:momentsa collection of numbers:count, :mean, :sd(count = 200, mean = 3.1, sd = 0.4)
:quantilesa collection of numbersprobs, named by percentage(q10 = …, q50 = …, q90 = …)
base = preset_summaries(:vector; names = (:a, :b))
summary_keys(base)                              # [:a, :b]
namedtuple_to_vector(compute_summary(base, [10.0, 20.0]))   # [10.0, 20.0]

pop = preset_summaries(:moments)                # count/mean/sd over samples
compute_summary(pop, [1.0, 2.0, 3.0, 4.0])      # (count = 4, mean = 2.5, sd = 1.291…)

q = preset_summaries(:quantiles; probs = (0.25, 0.75))
summary_keys(q)                                 # [:q25, :q75]

name renames the summary itself (its key for :scalar, its name for the composite presets); :vector takes names (one Symbol per entry) or d (defaults :v1 … :vd); :quantiles takes probs, defaulting to (0.1, 0.5, 0.9) and named by percentage (0.975 becomes :q97_5). Passing a keyword the chosen preset does not use is an error, and so is a key clash with another part when the preset is composed — keys are not silently dropped or renamed.

The result is an ordinary summary (FunctionSummary or CompositeSummary): compose it with compose, rescale it with scale, reduce it with pca_reduce, or average replicates with aggregate, exactly as any hand-written summary.
